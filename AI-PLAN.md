# AI-PLAN — AI-вкладка журнала (ветка `ai-dev`)

Спецификация зафиксирована по итогам интервью (grilling). Источник решений — сессия
согласования AI-вкладки. Всё ниже — согласованные решения, не предложения.

## Принципы

- OpenAI-compatible API: `GET {base}/models` и `POST {base}/chat/completions`.
- Прокси TradeJournal между пользователем и поставщиком **нет** — данные идут
  напрямую на Base URL. Это явно проговаривается в согласии.
- Ключ — личный API-ключ пользователя. Никаких SDK, только `fetch`.
- Разделы настроек приложения, API-ключ, способ хранения, история подключений и
  тела ошибок **никогда** не отправляются модели.

## Подключение

| Решение | Значение |
|---|---|
| Base URL | Пустое поле, плейсхолдер `https://api.openai.com/v1` (пусто → дефолт) |
| Валидация URL | Только `https://` или `http://` (любой хост, без доп. ограничений) |
| Проверка | Успешный `GET /models`; токены не тратятся |
| Сноска успеха | «Успешное подключение! Доступно моделей: N» — в настройках и во вкладке |
| Список моделей | После ввода ключа + кнопка ручного обновления (поставщик мог обновить модели) |
| Группировка | Поставщик = домен Base URL (известные — человекочитаемо: OpenAI, OpenRouter, xAI…), внутри — семейства (`gpt`, `o`, `claude`, `gemini`, `grok`, …) |
| Модель недоступна | Сохранить выбор, пометить «модель недоступна», заблокировать отправку, предложить список |
| Ручной ввод модели | Недоступен: при ошибке `GET /models` подключение считается неуспешным; показывается причина + тело ответа в отдельной сноске |

## Модель и мышление

- В чате — компактный селектор модели; popup: поиск, группы по поставщикам,
  галочка у выбранной, снизу — уровни мышления (референс: pi).
- Модели без описания в API — «возможности не указаны».
- Thinking: карта известных семейств + metadata; если данных нет — «неизвестно»;
  если модель не поддерживает — явная надпись «Модель не поддерживает выбор
  уровня мышления». Уровни: Low / Medium / High / Max.
- Модель и thinking — общие настройки по умолчанию; история сохраняет фактическую
  модель и thinking каждого ответа (подпись у каждого ответа ассистента).

## Хранение ключа

| Среда | Варианты |
|---|---|
| Tauri | «В памяти» или файл AppData `ai-key.json` (открытый текст, **без шифрования** — решение пользователя) |
| Браузер | «В памяти» (до перезагрузки) или `localStorage` |
| Момент выбора | Каждый раз при сохранении ключа — явный выбор, без запоминания |
| Предупреждение | Рядом с сохранением на устройство: ключ хранится открытым текстом |
| Удаление ключа | Удаляет ключ и данные подключения; история чата сохраняется |

## Согласие и данные

- Первый вход на вкладку с подключённым ключом → предупреждение во весь блок,
  перекрывает чат до «Согласен». Текст: данные отправляются напрямую поставщику
  по Base URL; TradeJournal не использует прокси и не контролирует обработку
  данных поставщиком. Список разрешённых разделов — в согласии.
- Разделы: **Сделки, Комментарии, Заметки, Вложения (изображения)**.
- Пресеты + реактивные чекбоксы: «Минимум» (сделки), «Рабочий контекст»
  (+комментарии, заметки), «Разрешить всё» (всё, включая вложения), «Своё».
- Изменение разрешений — в настройках. Уже отправленные данные из истории не
  удаляются; история удаляется только вручную.
- Вложения: только vision-моделям; иначе диалог «убрать вложения / выбрать
  vision-модель». Вложения могут содержать персональные данные — отдельное
  предупреждение в «Разрешить всё».

## Файлы контекста (системные)

- Два файла: `AGENT.md` (все поставщики) и `CLAUDE.md` (модели Anthropic:
  `claude-*`, `opus`, `sonnet`, `haiku`). Других имён нет.
- Каждый — отдельная кнопка и отдельная модалка с большим полем; содержимое
  вводится вручную (HTML экранируется при выводе), кнопка «Сохранить», кнопка
  «Очистить»; общий «Сбросить все файлы» в настройках.
- Роль — системный контекст проекта: отправляется как system-сообщение (одним
  сообщением с заголовками файлов), ко всем запросам активной сессии.
- Выбор: чекбоксы в настройках; активный файл показывается в popup модели.
- Anthropic-модель + пустой `CLAUDE.md` → системный файл не отправляется
  (сноска в настройках поясняет: «CLAUDE.md — для моделей Anthropic (Opus и др.)»).
- Отключение чекбокса сохраняет текст, но перестаёт отправлять.
- `SYSTEM.md` — исключён из списка.

## Чат и сессии

- Сессии: локально (браузер — `localStorage`, Tauri — AppData `ai-chat.json`).
- Сессия создаётся первым сообщением (пустых сессий нет).
- Пустое состояние: центрированное поле ввода + быстрые кнопки внизу.
- Название сессии — из первой фразы пользователя; переименование (кнопка рядом с
  удалением переводит название в поле ввода) и удаление сессии (с подтверждением).
- «Удалить всю историю» — с подтверждением; в настройках — размер, число бесед и
  сообщений, реактивно.
- Список сессий — боковой блок, у каждой кнопки «переименовать» и «удалить».
- Сообщение хранит: роль, текст, время, модель, thinking, статус (ok / остановлен /
  ошибка), usage-токены и стоимость (если известна). Полный отправленный контекст
  не хранится. Тело ошибки не сохраняется — это временная сноска.

## Быстрые кнопки (фиксированный набор)

1. **Анализ открытых сделок** — селект «Все открытые» / конкретная сделка.
2. **Ошибки и паттерны**.
3. **Итоги за период** — Сегодня / 7д / 30д / Месяц / Квартал / Год / свой диапазон.
4. **Рекомендации по улучшению**.
5. **Вопрос по журналу** — фокус в свободный ввод.

- Нажатие отправляет сразу (согласие уже дано).
- Несовместимые с моделью кнопки отключаются с объяснением причины.
- Во время генерации новый запуск → диалог «Остановить текущий» / «Дождаться».

## Поток и ошибки

- Потоковый вывод + кнопка остановки; остановленный ответ сохраняется с пометкой
  «Ответ остановлен».
- Endpoint без streaming → обычный запрос целиком + предупреждение (фолбэк только
  если стрим не вернул ни символа).
- Ошибка в потоке → частичный ответ + раскрываемая сноска; без автоповтора.
- Ошибка подключения/запроса → безопасная причина + тело ответа в отдельной
  экранированной сноске (максимум 8 КБ); значения полей сохраняются.
- Контекст не режется локально: отправляем всё; ошибку лимита отдаёт поставщик.
- Usage после ответа: токены входа/выхода/всего; стоимость — только если цены
  пришли в metadata `/models` в известном формате, иначе «Стоимость неизвестна».
- Смена модели посреди сессии разрешена; каждый ответ подписан моделью.

## Безопасность и CSP

- CSP ослабляется точечно только для исходящих запросов:
  `connect-src … https: http://localhost:* http://127.0.0.1:*`.
- Ключ не логируется, не попадает в консоль, историю и экспорт.
- Существующий экспорт журнала в приложении отсутствует; при появлении экспорта —
  отдельный чекбокс «Включить историю AI».

## Что НЕ входит (MVP)

- Эмбеддинги/локальный индекс журнала, конструктор кнопок, temperature, лимит
  ответа, автоматические фоновые запросы, оценка стоимости до отправки,
  прокси-сервер, шифрование ключа.

## Порядок реализации

1. Слой `src/lib/ai/`: типы, API-клиент, хранение ключа, контекст, сессии, стор.
2. Компоненты: селектор модели, подключение, согласие, сессии, быстрые кнопки.
3. Страница `/ai` + страница «Настройки» (+ пункт навигации).
4. CSP, смоук-тесты чистых функций, `npm run check` + `npm test`.
